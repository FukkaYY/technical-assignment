# テスト方針

2週間のため網羅率の数値目標は置かず、権限境界と必須ユーザーフローを優先する。

## Rails model

- メールアドレスの正規化と一意性
- roleの許容値
- プロフィール項目の検証
- 関連と削除方針
- パスワード認証
- 会話参加者と送信者の整合性

## Rails request

- 学生登録
- ログイン、ログアウト、`GET /me`
- 学生一覧・詳細
- メッセージ送信・会話取得
- 401、403、404、422
- レスポンスに非公開項目が含まれないこと

## Next.js

- ESLintで静的解析する。
- `next build`でTypeScriptと本番ビルドを検証する。
- 主要なフォーム、一覧、詳細、読み込み・空・エラー状態、ページ移動、送信状態はPlaywrightのE2Eで検証する。

## E2E

1. 企業ログイン、学生検索・詳細、メッセージ送信
2. 募集の作成、学生側の一覧・詳細確認、募集終了
3. 面談予定の提案、学生の承諾、企業側の承諾確認
4. 学生プロフィール編集、公開停止、企業側の非表示、既存会話の継続、再公開
5. 学生の受信・返信・未読解除
6. 学生セッションから企業画面へアクセスできないこと

PlaywrightのChromiumで主要フローを連続実行する。Docker ComposeでアプリとDBを起動し、seedのデモ企業・デモ学生を利用する。GitHub Actionsでは通常のfrontend・backendジョブと分離し、失敗時にHTMLレポート、スクリーンショット、動画、trace、コンテナログをartifactとして7日間保存する。
