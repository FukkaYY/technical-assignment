# 企業ログイン

## 目的

許可された企業担当者だけが学生情報とメッセージ機能へアクセスできるようにする。

## 優先度・区分

- 優先度: P0
- 設計判断: 企業の公開登録は実装せず、デモ用企業アカウントをseedで用意する。

## 対象ユーザー

seedで登録済みの企業担当者。

## seedデータ

| 項目 | 開発・テスト用の初期値 |
|---|---|
| 企業名 | デモ企業株式会社 |
| メールアドレス | `company@example.com` |
| パスワード | `password123` |

- 初期値はダミーデータとし、実在する担当者の情報を使用しない。
- seedは再実行可能とし、同じメールアドレスのユーザーを重複作成しない。
- 本番環境でseedを実行する場合は、メールアドレスとパスワードを `DEMO_COMPANY_EMAIL` と `DEMO_COMPANY_PASSWORD` から必須で取得する。

## フロー

1. 企業ログイン画面でメールアドレスとパスワードを入力する。
2. 画面はメールアドレス、パスワード、`role=company` を送信する。
3. Railsが資格情報と保存済みロールを検証する。クライアント指定のroleを権限付与に使用しない。
4. 成功時は既存セッションを再生成し、学生一覧へ遷移する。
5. 失敗時は資格情報のどちらが誤っているかを特定しない共通エラーを表示する。

## API

- `POST /api/v1/session`: 学生・企業共通のログイン
- `DELETE /api/v1/session`: ログアウト
- `GET /api/v1/me`: 現在のユーザーとロールを取得

### ログインリクエスト

```json
{
  "session": {
    "email": "company@example.com",
    "password": "password123",
    "role": "company"
  }
}
```

- `role` は `student` または `company` とし、該当ロールへのログイン対象を絞るために使用する。
- 成功: `200 OK`。企業の場合は `data.user` の `id`, `email`, `role` と、`data.company_profile` の `id`, `user_id`, `company_name` を返す。
- 資格情報またはロールの不一致: `401 Unauthorized`。`base` / `invalid_credentials` / `メールアドレスまたはパスワードが正しくありません` の共通エラーを返す。
- ログイン試行制限の超過: `429 Too Many Requests`。`base` / `rate_limited` を返す。

## セキュリティ

- RailsセッションとHttpOnly Cookieを使用する。
- Cookieには本番環境で `Secure` と適切な `SameSite` を設定する。
- ログイン失敗時にアカウントの存在を漏らさない。
- `POST /api/v1/session` の成否を含むすべての試行をIPアドレス単位で計数し、60秒間に5回まで許可する。6回目以降は `429` を返す。
- 学生ロールで企業画面・企業APIを利用できない。

## 画面と遷移

- 企業ログイン成功後は `/students` へ遷移する。
- 学生一覧実装前の `/students` は、企業名、ログイン成功状態、ログアウト導線だけを表示する。
- ログイン済み企業が企業ログイン画面へアクセスした場合は `/students` へ遷移する。ログイン済み学生の場合は企業ログインフォームを表示し、企業アカウントでのログイン成功時にセッションを切り替える。
- 学生ログイン画面は `/students/login` とし、共通ログインAPIへ学生ロールを指定する。

## 受け入れ条件

- seed企業でログインし、学生一覧へ遷移できる。
- 誤った資格情報ではセッションを作成しない。
- 学生資格情報を企業ログインに使用してもセッションを作成しない。
- 学生アカウントでは企業向けAPIにアクセスできない。
- ログアウト後は保護されたAPIを利用できない。
