# 認可

## ロール

- `student`: 自身のプロフィールと受信会話へアクセスする。
- `student`: 公開中の募集を閲覧し、自身の「気になる！」だけを登録・解除する。
- `company`: 学生一覧・詳細と、自社の会話へアクセスする。
- `company`: 自社の募集を作成・編集・募集終了にできる。

## 原則

- 画面制御だけでなくRails側で必ず認可する。
- クライアントから渡されたroleを信用しない。
- 所有者・参加者の判定はログイン中ユーザーから行う。
- 企業向け会話一覧と学生別メッセージAPIは、ログイン中企業が参加する会話だけを取得・更新し、他社の会話を返さない。
- 学生向け受信APIはログイン中学生が参加する会話だけを返し、他の学生の会話は404として存在を隠す。
- 予定提案・取消は会話の企業、承諾・辞退は会話の学生だけが実行できる。
- プロフィールの公開状態は学生本人だけが変更できる。
- 非公開学生は企業向け一覧・検索・詳細から隠し、既存会話がある企業だけがその会話を継続できる。
- 募集画像は認証済み利用者に限り、学生には公開中の募集、企業には公開中または自社の募集だけを返す。

## 企業認可の共通処理

- 企業専用APIは共通の企業認可処理を使用する。
- 未ログインは `401 Unauthorized` と `base` / `unauthenticated` を返す。
- 学生ロールは `403 Forbidden` と `base` / `forbidden` を返す。
- フロントエンドの画面制御は利便性のために行い、API側の認可に代用しない。

## アクセス表

| リソース | 未ログイン | student | company |
|---|---:|---:|---:|
| 学生登録 | 可 | 不要 | 不要 |
| `GET /me` | 401 | 可 | 可 |
| 学生一覧・詳細 | 401 | 403 | 可 |
| 企業からの送信 | 401 | 403 | 可 |
| 学生の受信会話 | 401 | 本人のみ | 自社参加分のみ |
| 公開中の募集一覧・詳細 | 401 | 可 | 403 |
| 募集の気になる登録・解除 | 401 | 本人分のみ | 403 |
| 募集サムネイル | 401 | 公開中のみ | 公開中または自社分のみ |
| 募集の企業管理 | 401 | 403 | 自社分のみ |
| 面談予定 | 401 | 本人分の承諾・辞退 | 自社分の提案・取消 |
| プロフィール公開状態の変更 | 401 | 本人のみ | 403 |

## 情報公開

- 企業向け学生APIにメールアドレスを含めない。
- 学生向け企業情報はP0では企業名だけを返す。
- 存在を隠す必要があるリソースでは403と404の使い分けを検討する。
